# 同室行动验证 · Windows

**共享房间、真实聊天和白名单动作接口已跑通。自然地发起移动仍是主要缺口。** 五分钟实录中，模型在进入、靠近、坐下和离开等事件上全部选了说话。走路、坐起的能力另在真实 Godot 场景中定向测试。

## 复现

使用 Godot 4.6.3 Windows Standard，Python 使用本项目后端环境。在独立 checkout 中运行以下命令。环境变量 DEEPSEEK_API_KEY 由启动者提供。启动器生成一次性本机 token，监听 127.0.0.1:18471，关闭 Godot 后回收服务。Godot 子进程只接收房间 token 和必要的系统环境变量。

    godot --headless --editor --path godot_room --import
    python godot_room/tools/run_room.py <Godot可执行文件路径>

WASD 移动，Shift 加速，空格跳，鼠标转向，V 切换视角。E 对准座位坐下，再按 E 起身。对准书本可拿起，靠近并对准 AI 可递出。Enter 输入并发送文字。实时聊天调用现有 /api/chat，回复显示在角色头顶。

单独运行导入、动画验证或导出：

    godot --path godot_room --fixed-fps 60 --script res://import_probe.gd
    godot --headless --path godot_room --fixed-fps 60 --script res://check_navigation.gd
    godot --headless --path godot_room --export-release "Windows Desktop" build/Room.exe

最后一项需要 Windows x86_64 release 模板和 build 目录。发布前要随发行物提供本项目、引擎、插件和素材的许可说明。

## 五分钟真实运行

录制只捕获 Godot 视口。用户侧使用定时移动、视角、交互和输入事件，模型正常联网。用户侧时间线可查 tools/acceptance_tour.gd。所得视频为 960×540、8 fps、300 秒，无音轨。8 fps 是采集频率。引擎按 60 fps 渲染。此次使用千驮谷筱，视频保存在本机忽略目录 tmp_ui_smoke/godot-room-deepseek-5min.mp4。

| 时间 | 实际行为 |
| --- | --- |
| 0–12 秒 | 双方相隔约 4.9 米，进入房间触发真实决定，角色显示简短问候。 |
| 12–55 秒 | 用户走近到约 1.48 米，角色转向并出现交谈提示，再次收到 say 决定。 |
| 55–95 秒 | 用户输入“馨语，晚上好！这个房间里你最喜欢哪里？”。/api/chat 往返 8.12 秒，角色头顶显示 72 字。回复中说自己没有真正的房间，暴露出聊天提示和空间感知尚未对齐。 |
| 95–190 秒 | 用户走到沙发，经交互坐下。模型继续说话，没有自行坐到旁边。 |
| 190–300 秒 | 用户起身，V 切到越肩视角并走开，距离约 5.38 米。模型继续说话，没有跟来。 |

DeepSeek Flash 的 9 次意图决定均为 say，另有 1 次普通聊天。10 次 HTTP 全部返回 200。意图请求到客户端开始执行为约 5.40–9.05 秒，中位 5.87 秒。靠近事件对应 5.87 秒。本地转向无需等待网络，按物理 tick 更新；未做输入设备到屏幕的延迟测量。第一次录制因聊天默认 30 秒限时收到 500。复录在隔离配置中启用直接回复、关闭内心独白，聊天限时 90 秒。

供应商返回本轮 6,394 tokens，包括命中缓存输入 3,840、未命中输入 2,224、输出 330。按相同事件密度折算约 120 次调用/小时（108 次意图、12 次聊天）。按每百万 tokens 在低峰/高峰的美元单价分别为 0.003/0.006、0.15/0.30、0.60/1.20，约 **0.0065–0.0130 美元/小时**。这是此次负载的外推，实际取决于交互频率和缓存命中。见 [DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。

## 渲染、物理与动画

- RTX 5060 Laptop GPU，Forward+、直接点光源、实时阴影、SSAO、ACES。除启动样本外，录像期间每五秒采样的引擎 FPS 中位数为 60。Windows 进程采样约 21 秒，平均整机 CPU 2.40%，Godot 进程 GPU 3D 引擎 4.31%。采样在录制时进行，不能作为其他机器的性能保证。
- 使用地板、墙和家具碰撞体烘焙出 24 个导航多边形。真实引擎定向测试中，角色从起点到椅子落位的净位移 3.41 米，进入 Sitting_Idle，再经起身回到 Idle。曾因座位中心高于地面导致已接近仍持续步行，现以角色地面高度计算接近点。
- Quaternius Standard 提供 Idle、Walk、Sitting_Enter、Sitting_Exit、Sitting_Idle 等动画。导入后 Godot 移除了名称中的 _Loop，源骨骼以 DEF 开头，不能按 VRM 名直接播放。运行时用源与目标的静止骨骼坐标转换旋转，髋部只转移按身高缩放的竖直位移，水平运动由碰撞体控制。AnimationTree 使用 0.22 秒过渡。座面高度和不同身材的精确贴合仍需单独调校。
- 初版双段校正的支撑脚水平偏移 P95 为 7.5 厘米。增加最多12厘米的骨盆让位后，同一路径中位数低于0.01毫米，P95 为1.3毫米。指标只统计支撑阶段的脚踝水平位置，步态换相、骨盆补偿的观感仍需人工验收。此为单模型单路径测试。
- 导入兼容性和骨骼详见 [导入记录](README.md)。4.7.2 下失败的是 springBone、materials_mtoon 和 materials_hdr_emissiveMultiplier 插件脚本，两个空引用诊断分别来自解析与扩展枚举。4.6.3 实测 149 根骨骼，能渲染皮肤、头发和衣物。Joy 整体表情可见，A 嘴型权重实测为 0.65，未做语音音素时间同步。左右摆头、移动时头发和裙摆关节出现相对旋转。对比图见 [正面](docs/spike/shino-020.png)、[侧面](docs/spike/shino-050.png)、[Joy](docs/spike/shino-075.png)。
- [Godot](docs/spike/godot-room.png) 与 [three.js](docs/spike/three-room.png) 均为千驮谷筱，机位 (0,1.7,3.65)，目标 (0,0.95,0)，垂直 FOV 50°。Godot 阴影让沙发、桌子和人物与地面接触关系更清楚，但窗口过亮，角色正面偏暗。three.js 的夜间布景更丰富。截图比较的是两套实际房间，材质与灯位并不相同。
- Windows x64 导出包含 EXE 104,659,456 字节和 PCK 约 21.9 MB，合计约 120.7 MiB。导出程序离屏启动、烘焙导航及加载角色测试通过。导出文件仅保存在本地 build/。

## 接入边界与建议

实验接口 /api/room/intent 默认关闭，沿用现有 token 和 Origin 检查，还要求配置启用 token 鉴权。最多读取 8 KiB，一次处理一个决策。输出仅能指向世界中的用户、已报告物件或房间界限内坐标。入座需目标具备 sit 标签。运行期本地执行转向、注视、避让、步行与坐姿，网络超时退回 idle。坐标界限检查与实际可达性是两层，仍需补充拥堵、目标被占用和无法到达的行为测试。

建议 Electron 主进程提供可选的“进入房间”，启动同一用户会话的 Godot 子进程，通过子进程环境传递短效 token 与回环端口。桌宠窗口保留退出入口，房间显示期间暂停重复的渲染与主动发言，角色会话、聊天和记忆仍由同一后端持有。下一阶段先对齐聊天与意图对房间的认知，向决策提供上次行为和完成结果，测量自发移动比例、打断和切换座位，再扩大房间美术。录像后的脚锁、气泡换行及部分手势改动分别做了本地验证，五分钟录像没有覆盖这些后续改动的完整组合。

Godot、godot-vrm、MToon、Shino 和 Quaternius 的来源与许可见 [依赖记录](README.md)。房间几何由代码生成。

**补充真实指令测试（独立于上述五分钟统计）**：用户说“请你现在实际走到椅子旁坐下”。第一次模型只说话。明确区分聊天回复与下一步身体意图，并加入经隐私过滤的最近用户原话后，复测得到 go_to(chair)，决策往返 8.82 秒，角色通过导航从 (-1,0,-2) 移至 (1.25,0,-1.97) 后待机。该轮真正执行了走向椅子的动作，未继续下发 sit_on。多步目标完成仍需研究，报告中的坐下与起身能力依据定向测试。

越肩相机靠墙定向测试：弹簧臂从2.1米缩至0.623米，镜头z=3.9234，墙面内边界z=3.925。跳跃顶点0.91米，随后落地并成功恢复第一人称。

完整本地检查：1108项 Python 测试通过、3项跳过，86组 Node 测试通过，语法及秘密扫描通过。导出包最终 PCK 为21,898,440字节。录像经 ffprobe 确认300秒，并已完整解码。
