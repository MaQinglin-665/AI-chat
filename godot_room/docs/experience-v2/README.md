## 延迟与费用

用户每次发话只调用一次模型。房间后端按行发送已过滤的语句和最终身体计划。Godot 按帧读取回环 HTTP 数据，首个可朗读的句子或分句到达即送合成，后续片段顺序衔接。旧客户端仍接收完整 JSON。语音使用角色上的 AudioStreamPlayer3D，嘴型以实际播放时钟和角色音频总线驱动。

四轮均有正常回复。小于 2.5 秒的 P50 目标尚未达到。耗时主要发生在首句抵达之前，包含本地组装上下文、上游网络和模型出句，目前没有单独拆分这三段。首句抵达后的合成、传输及播放合计约 0.20 秒。以上按应用时间戳和音频混音采样估算，非扬声器外部麦克风测量。

主录的 DeepSeek Flash 用量记录共 11 次、10,138 tokens，其中输入缓存命中 3,840、未命中 5,823、输出 475。按每百万 token 分别 0.003/0.15/0.60 美元估算，非高峰 **$0.00117**，同频率约 **$0.0138/小时**，高峰价约为两倍。单独的回顾请求、补拍及调试轮次不计入主录用量。[官方计价](https://api-docs.deepseek.com/quick_start/pricing/)

## 行为与回顾

主录收到 30 个计划，包括 17 个本地活动/效用计划、7 个用户计划和 6 个模型自主计划。为保证覆盖，定时脚本指定的展示计划也列入本地组，分布不能用于推断日常随机发生率。体验回执按实际进入活动或交互成功计数。呼唤 3、击掌 2、用户递书 1、摸头 1、她递书 1、阅读 2、整理书架 2、伸展 2、打哈欠 2、小睡 1、窗边发呆 1、并排看窗外 2。另一次实机录得靠近唤醒。

实验使用真实 DeepSeek 和 Windows Huihui 音色。退出房间后，将这一轮真实隐藏回执及对话送入桌宠普通聊天接口，询问“刚才我们在房间里做了什么？”，实际答“我们一起看了窗外，后来我打了个哈欠。”。验收通过接口复验桌宠回顾；录像结束于房间内。交互只传白名单事实，未知事件被丢弃。

Godot 4.6.3 另测导航、座位、玩家相机、共享目标、语音口型和美术交互契约。Python/Node 覆盖分段提前交付、动作回执和回顾过滤。脚步声按实际水平位移触发，通过地毯碰撞盒选材质。四个单声道音效由本项目原创合成，CC0，分别位于玩家与角色的 3D 声源上。动作复用现有 Quaternius 片段，加视线、手部目标与骨骼姿态。当前交互侧重反应和安全距离，没有真实身体接触求解。
