# 第五阶段 · 可选房间组件与收尾验证

## 正式组件 v1.0.0

[正式 Release](https://github.com/MaQinglin-665/AI-chat/releases/tag/room-component-v1.0.0) 使用已验证的 rc2 原始 ZIP，74,047,830 字节，SHA256 为 `f98a2ea84cbc125f60cbc3f2443984e4fef03eb73d569454c2f9441bfcb3c324`。发布清单作为独立附件，构建工具从最终 ZIP 生成同格式清单。Electron 内置八个文件的完整相对路径、大小和摘要，运行时不信任下载的清单。

安装时校验 ZIP，再遍历暂存树。每次启动前用同一规则校验缓存。仅允许清单中的八个普通文件和它们必需的父目录；多余文件或目录、缺失、内容被改、硬链接或符号链接都不能作为有效组件启动。损坏缓存会被移除并提示重新进入下载。仅接受 GitHub Release 的 release-assets 和 objects 两个 HTTPS 主机，路径限定仓库编号。

床沿完成回执从命名 Seat bed_edge_seat 映射为“坐到床沿”。此前遗漏发生在回顾选句时。现在即使模型只回答窗边，也保留已确认的床沿入座事实。修复测试覆盖两个目的地和最后只回答窗边的情况。

### 正式版实机验收

全新隔离用户目录，开启开关，从确认下载正式组件到启动 79.12 秒。真实 DeepSeek 两轮分别回应“行，我挪过去。”“行，这就去窗边。”。离场事实依次为走到床沿、坐到床沿、走到窗边、看向窗边；返回桌宠询问后答“我在床沿坐了会儿，后来朝窗边看了一眼。”。未显示内部记录，房间进程已退出。

本地成片 194.67 秒，30 fps，H.264/AAC，整片解码通过。片头使用真实设置及下载对话框关键帧压缩等待；房间内连续录制 170 秒，声音仅采集房间进程；片尾为真实桌宠回顾。输入由验收脚本驱动。第二次指令后角色有一段离开镜头，执行结果另以回执确认。正式版关键帧为 [06–11](docs/phase5/)。录制路径为忽略目录 tmp_ui_smoke/phase5-stable/room-v1.0.0-review.mp4。

发送时间戳与房间进程音轨比较，按10毫秒窗口中 RMS 首次超过100（16位 PCM）估计，分别为3.82和3.53秒，P50约3.68秒。样本仅两轮，未达到小于3秒目标。本次隔离副本将后端冷启动的等待上限延长至180秒，未改产品超时。回顾可用性已直接验证，未单独验收桌宠模型的渲染恢复。

## 实现

- 房间离场回执改为独立 IPC 中的类型化事实，仅保留用户是否坐下和已完成的动作。聊天历史只包含真实话语。回顾请求才附带白名单事实作为隐藏上下文，模型表达经过事实核对。旧版内部记录在历史加载时清理，避免显示、翻译和朗读。
- 回顾按地点合并接近与落座等步骤，优先主要活动。未经完成回执确认的计划不能被说成已完成。
- TTS 按句号和分句标点拆分，Windows 音色进程预热并串行合成，准备下一段时播放当前段。音量口型继续跟随实际播放；网络请求移出渲染帧等待。浏览器模式使用本机同名 Huihui 音色的内存音频。
- 交互提示移到屏幕左下。新增床沿目标从美术 Seat 的 metadata 读取，支持接近、坐下和起身。床沿只有一个座位，已占用时拒绝第二人落座。
- 实验开关默认关闭，设置中显式开启；启动中和运行中锁定开关，关闭房间后恢复。关闭时不加载组件下载器与房间会话模块，后端实验路由也保持关闭。

## rc2 验证时的下载与发布边界

授权发布的独立组件预发布为 room-component-v1.0.0-rc2，Godot 4.6.3 Windows x64，ZIP 74,047,830字节（70.6 MiB）。应用固定下载地址与 SHA256，版本升级需要发布新的应用代码。初次下载需用户确认大小，已安装缓存每次启动重新校验 EXE/PCK。

ZIP SHA256 为 `f98a2ea84cbc125f60cbc3f2443984e4fef03eb73d569454c2f9441bfcb3c324`。

下载入口固定为本项目 GitHub Release 的 HTTPS URL，只允许重定向到仓库编号1217591333所属的 GitHub Release CDN 路径。四个1 MiB分段并行，每段有长度校验、超时及最多5次重试。完整 ZIP 长度和哈希通过后才解压，再校验两个运行文件。失败清理暂存文件。组件安装到 Electron userData 下，启动票据仅经进程环境传递。

Linux 工作流校验固定 Godot editor/templates 摘要，导入、导航、用户移动、共享目标、口型及美术交互契约通过后交叉导出 Windows。独立标签创建预发布；普通 Release 只增加房间 ZIP 和校验文件附件。现有桌宠安装包流程不嵌入 EXE、PCK 或 VRM。组件 ZIP 携带 Godot、插件、模型、动画及美术许可。

## 此前的 rc1/rc2 验收记录

1. 使用独立 Electron 用户目录、回环端口、环境变量凭据和系统音色。默认关闭，在设置显式开启。rc2 真正从发布地址下载到空缓存，从确认到启动 Room.exe 约 201 秒。下载成品已与独立拉取的发布资产核对。
2. rc1 真机两轮对话产生床沿和窗边的完成回执。回桌宠后的共享历史含两轮对话和回顾问答；隐藏事实含走到床沿、坐到床沿、走到窗边、看向窗边。聊天界面未出现内部记录，渲染恢复。实际回顾为“我看了看窗边。”，事实正确但省略了床沿。
3. 第四阶段发送到开口 P50 为 4.24 秒。分段合成和预热后，rc1 两轮实测约 2.84、3.25 秒，P50 **3.05 秒**。按发送时间戳和房间进程的真实音轨测量，有约一个音频采样块的起点不确定性。模型处理约 2.51、2.86 秒，热态单段合成约 30～63 毫秒。尚不能确认达到小于 3 秒的目标。
4. rc2 将 HTTP 传输移出渲染线程。最后复测时系统可用内存一度降至约 0.5 GiB，隔离 Electron 首次启动的 20 秒超时；仅验收副本延长启动等待后已正常安装并启动。录像在第一轮键盘输入前因窗口无法获焦中断。此轮没有完整的两轮对话或可报告的 rc2 延迟，待恢复窗口连接后补录。验收实例和日志独立于私人配置。

已核验的关键帧位于 [docs/phase5](docs/phase5)。01–02 为 rc2 设置；03 为 rc1 同款 70.6 MiB 原生确认框；04–05 为 rc1 房间对话和返回后的实际回顾。rc2 的原生确认框虽被识别并实际触发，截屏是白帧，未作为证据提交。

## 已知限制

- 组件完整性验证依赖固定 SHA256 与 HTTPS，组件尚无 Windows 代码签名。更新组件必须同时审查新的固定摘要。
- 本机语音桥仅验收 Windows Huihui；其他 TTS 服务沿用原接口，未逐一供应商复测。
- 回顾使用白名单事实与保守校验，遇到不符合事实约束的自由表达会回退为简短句子。当前离场事实保留在会话内存，重启不会恢复这些隐藏回执。
- 无窗口 Godot 测试退出仍有 ObjectDB 清理告警，正常游戏退出由 Electron 回收子进程。
- 当前是技术验证，房间美术、导航动态避让与表情自然度仍需作者体验验收。
