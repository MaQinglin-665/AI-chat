## 范围

基线 `887bc80`，分支 `codex/memory-log-read-efficiency-20260922`，沿用隔离工作区。只改进学习审计/影子日志的最近记录读取，不改变记忆保存格式、备份、内容和配置。已查看保存路径及锁，但没有足够证据认定保存逻辑存在本轮应修的并发问题，因此未修改写入行为。

## 问题与修复

`memory_store.tail_jsonl` 原来读取并拆分完整文件，再截取最后几行。记忆状态面板读取最近 5 条、诊断读取最近 80 条等调用都承担整份日志的读取成本。原来的 `[-0:]` 还使 0 或负数限制返回全量记录。

现在以二进制块从末尾反向读取，找到足够完整的行后再解码和解析；避免块边界截断中文或表情符号。数量不大于 0 时直接返回空列表。仍按最后 N 个物理行选择，空白行不补位；损坏 JSON 和非字典值保留原有 raw 展示。支持 UTF-8 BOM、LF、CRLF、无末尾换行及长行。旧式纯 CR 文件仍可读取，但会扫描全文件；长单条记录所需读取量仍取决于记录长度，不承诺固定内存上限。

文件缺失、无法读取时仍安全返回空列表。读取从打开时的文件长度开始，不把并发追加当作完整文件快照保证。

## 证据

- 修改前新增回归 3 失败、9 通过：零/负数限制错误，读取整份日志超过测试的读取预算。
- 修改后新增 15 项全部通过，包含跨多个块的中文/emoji 长记录。
- 12,650,018 字节合成日志取末两条，测试验证总读取不超过 8,192 字节。仅证明该场景的读取量改善，不声称整机速度提升比例。
- 相关记忆/Obsidian 回归及静态检查最终结果见 progress.md 本轮记录。
