# VRM 性能与动作复测（2026-10-25）

## 诊断方法与结论

在同一台 Windows 机器、Electron 39.8.10 上启动本仓库真实 `electron/main.js`，
分别显示完整窗口和最小化完整窗口后的桌宠。完整窗口修复前 1380×898、修复后 1382×898 CSS 像素（窗口恢复产生 2px 宽度差），
桌宠 1708×1068，系统 DPR 1.5。每阶段预热 1.8 秒，再采样约 10 秒。
CPU 为 Electron 各进程 percentCPUUsage 之和；GPU 为这些进程的 Windows GPU Engine
3D 浮点计数器之和；内存为各进程 working set 之和，包含共享页重复计数，并非独占内存。
说话阶段使用已有 avatar-intent 入口注入起伏音量，不调用 LLM/TTS，数据不包含合成开销。

启动前未发现残留桌宠实例。已有语音服务不计入 Electron 数值。隐藏的另一窗口帧数不增长，
没有发现两个窗口同时绘制的证据。两种视图都初始化后仍各保留模型/纹理，内存并未明显下降。

主要瓶颈是桌宠每 100ms 一次的完整蒙皮网格 raycast：额外诊断采样中 97 次调用，
平均 101.75ms、最大 117.9ms，10.18 秒内累计 9.87 秒。现在用随骨骼更新的 12 个屏幕胶囊区域
判断鼠标是否落在角色附近，复测平均约 0.012ms。该近似不逐像素匹配发丝和衣物边缘。
完整窗口主要优化像素填充与合成开销：关闭抗锯齿、阴影和 VRM 全画布 CSS 阴影滤镜，
限制渲染像素并降低待机帧率。单次 update 平均仍约 2.5–2.9ms，没有把网格更新成本误称为消失。

只读模型统计：17,836,280 bytes（17.01 MiB），36 张内嵌图片/36 个纹理，最大 2048×2048。
不存在超过 2048 的纹理，因此没有做内存缩图，也没有修改模型文件。
RGBA 基础纹理估算约 146.5 MiB，含 mipmap 约 195.3 MiB；这只是尺寸估算，不是显存实测。

| 场景 | FPS 前 → 后 | CPU 前 → 后 | GPU 3D 前 → 后 | 工作集 MiB 前 → 后 |

| 完整窗口模拟说话 | 27.32 → 29.99 | 8.40% → 6.65% | 15.25% → 7.50% | 1052.3 → 1063.2 |

桌宠 GPU 占用上升是恢复正常绘制频率后的结果，不能声称所有指标都下降。
完整窗口画布从 2070×1347 降到 1176×764；桌宠从 2562×1602 降到 1199×750。
动态 DPR 分别约 0.852、0.702；较低分辨率与关闭抗锯齿会让轮廓略显锯齿，需用户权衡视觉效果。

完整窗口页面启动至可观测 renderer 就绪：3.74s → 3.97s；桌宠激活至就绪：722ms → 653ms。
后者不包括桌宠在后台等待完整窗口最小化的时间。新增内部 load 计时为完整窗口 517ms、桌宠 555ms，
不包含页面启动和首帧 shader 编译，不能与前述启动耗时混为一谈。加载阶段不是持续卡顿的主因，
本次没有证明冷启动时间改善。所有数值均为单机短时采样，不是跨硬件性能承诺。

## 动作、镜头与回收

所有动作幅度集中于 vrmRenderer.js 顶部 MOTION，质量、镜头、灯光分别为 QUALITY/CAMERA/LIGHT。
标准站姿手臂下放约 72 度、肘部微弯、手腕放松，VRM0/1 采用对应朝向。
呼吸驱动胸/脊柱/肩；重心和脊柱反向补偿；头部混合不同频率正弦；手臂随呼吸摆动。
固定种子的纯函数根据时间产生每 8–20 秒的小动作；说话音量驱动点头、前倾和手臂幅度。
挥手/点头结束或停止后回到同一时间的自然待机站姿，不回到 T/A 姿势。
镜头按身高和眼睛位置计算，脸位于上方三分之一附近、下缘到大腿附近；主光、弱补光及环境光保留 MToon。

运行时重启会回收旧帧循环、事件、频道和鼠标定时器。隐藏/不活跃时暂停 RAF，250ms 检查恢复，
完整窗口不建立桌宠鼠标轮询，穿透状态未变时不重复发 IPC。

## 边缘与桌宠展示修复（095c47f 后续）

前面的性能表记录 095c47f 阶段，以下是其后的同机对比，不能混用。
透明背景采用 premultipliedAlpha=true、黑色清屏 alpha=0；这原本就是 Three 的预乘默认值，
没有证据表明伪影来自错误清屏。主要可见问题是 DPR 约 0.702、未开 MSAA 时细 MToon 描边
和裁切透明贴图发生欠采样。保留作者的 MToon 描边参数、颜色与贴图，改用显式预乘透明、MSAA、
DPR 下限 1.0，并仅对 alphaTest>0 的非混合材质启用 alphaToCoverage（需要实际 MSAA samples>0）。
不改模型文件、源贴图、透明混合材质，也没有新增后处理依赖。描边仍存在，目标是平滑而非删掉模型原有线条。
90 万像素现为软预算：大窗口在 DPR=1 时可超过它，换取边缘清晰度。

共用页面 web/index.html 的 kawaii-stage-decor 包含星星、音符、爱心、闪光、猫和莲花。
原 visualPolish.css 仅隐藏 view=full，chatPolish.css 隐藏 view=chat；遗漏了 view=model。
现按视图隐藏整个装饰层，VRM/Hiyori 都适用。桌宠状态条移到左下角空白处、不再跟随角色脚部，
文本改为“馨语”。VRM 和 Hiyori 加载成功均设置 avatarReady，3 秒后开始 400ms 淡出；
减少动态效果偏好下则 3 秒后直接隐藏。主光 1.35→1.10，环境光 0.65→0.55，补光不变；
不对脸部材质单独改色，保留模型固有肤色差异。

### 实测

真实 Electron 桌宠 1708×1068 CSS 像素，每阶段预热后采样约 10 秒，CPU/GPU/工作集定义同上。
修复前为 095c47f；中间阶段用于区分更高分辨率的增量成本。

| 配置 | 待机 FPS | GPU 3D | CPU | 工作集 MiB |
| --- | ---: | ---: | ---: | ---: |
| 修复前，DPR 0.702，无 MSAA，有装饰 | 20.16 | 2.97% | 2.29% | 1395.7 |
| MSAA、去装饰，仍 DPR 0.702 | 20.04 | 0.62% | 1.26% | 1392.1 |
| 最终：MSAA、裁切覆盖率、DPR 1.0、去装饰 | 19.93 | 0.86% | 1.15% | 1372.4 |

最终 WebGL 实际 antialias=true，画布 1708×1068，28 draw calls、85,121 triangles。
GPU 总开销降低包含移除动画装饰及状态条的贡献，不能归因于抗锯齿让渲染更快。
短采样不代表所有设备；不支持 MSAA 的设备会跳过覆盖率处理。

真实 Hiyori 回归：未改私人配置，通过测试请求拦截选择 Live2D；就绪时状态条 label=馨语、left=12px、
decor display=none、opacity=1，3.6 秒后 opacity=0/visibility=hidden。
真实 VRM 最终截图确认无装饰/常驻状态条，局部对比确认脸、衣服轮廓不再明显呈断续像素线。
纯 Node 测试覆盖 DPR 下限、裁切/混合材质区别、无 MSAA 时不启用覆盖率及就绪标记。
