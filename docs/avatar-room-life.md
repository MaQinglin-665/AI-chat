## 日常与交互

`vrmWorld.js` 是无 WebGL 的纯调度/姿势/路径模块。TUNING、CONTACT、POINTS 和 OBSTACLES
集中定义时长、速度、幅度、手部接触点、活动点与家具占地；`vrmScene.layout()` 同时暴露这些布局信息。
坐姿使用位于家具外的安全接近点，抵达后平滑移到对应座面。桌面盆栽、相框、沙发靠垫依附其支撑家具，
不另占地面路径。路径采用膨胀家具矩形和可见图最短路，角色半径 0.22 米、步速 0.48 米/秒。

- 空闲 60–180 秒选下一个活动，固定种子、排除前一个活动；夜晚提高看书、坐下与打哈欠权重。
- 窗边扶窗/回头、伸手取书和手骨书道具、沙发坐姿轻晃、桌前托腮/书写、伸懒腰/打哈欠/轻晃。
  “哼歌”仅身体节奏，不产生音频，不调用 TTS。
- 输入、发送、正在处理对话或语音 hearing/release 阶段打断。常驻 armed 麦克风不会阻止日常。
  1.8 米内返回陪伴位，距离更远则原地面向镜头回应；对话结束后等待 20–40 秒再恢复。
- 离开坐姿先平滑站起再移动，现有嘴型、表情与说话动作继续运行。
  摄像机以指数平滑跟随位置，保留原有视场角与人物构图。
- 活动派发 `avatar-world-event`，detail 为 `{type:"activity",name,stage:"start"|"end"}`，仅 console.debug。
  不包含聊天内容，不写入记忆或持久日志，不修改对话/记忆/外部执行/Live2D 代码。

## 验证与限制

自动化覆盖所有活动点两两路径、边界、确定性序列、不重复、输入中断/延迟恢复、坐姿退出、
本地资源白名单、依赖完整性、加载失败回退、取消加载和资源释放；运行时测试覆盖输入/发送/语音忙碌信号和监听器清理。
安装包检查逐个比对选用素材和许可的 SHA256，确认发布源包包含完整依赖。

真实验收使用本机一份 VRM0：四个活动点、走路、输入打断、昼夜全景及十次房间切换。
没有调用真实 LLM/TTS/ASR 服务；语音信号链在自动化中模拟。未用真实 VRM1 复核所有活动。
这是程序生成的第一版姿势，不是动作捕捉；没有全身碰撞或脚底 IK，不同身高/衣裙可能需要接触点与坐姿微调。
镜头拉远的全景仅验收脚本临时覆盖，不改变产品默认构图。
截图/35 秒无声录像仅在 git 忽略目录 `tmp_ui_smoke/avatar-vrm-polish/`，不得上传到 PR。

## 本机性能与验收记录（2026-10-25）

同一份本地 VRM0、相同 Electron 窗口，1382×898 CSS / DPR 1，预热后采样约 10 秒。
CPU 是 Electron 进程之和；GPU 是其 Windows GPU Engine 3D 计数器之和；内存是进程工作集之和。

| 指标 | 改动前 | 家具与日常接入后（陪伴位待机） |
| --- | ---: | ---: |
| FPS | 19.99 | 19.98 |
| CPU | 3.28% | 3.32% |
| GPU 3D | 5.32% | 5.04% |
| 工作集 | 959 MiB | 970 MiB |
| Draw call | 38 | 36 |
| VRM 加载指标 | 431 ms | 449 ms |

GPU 约为基线的 0.95 倍，低于 1.5 倍预算；加载指标只计 VRM 加载，并不代表异步家具已全部就绪。
真实重复切换 room/none 10 次，渲染器资源稳定为 28 geometries / 47 textures，没有逐次增加。
该结果是短时本机采样，不是所有模型/显卡或长时间工作集无增长的保证；走路和手部接触运算的瞬时 CPU 会变化。
