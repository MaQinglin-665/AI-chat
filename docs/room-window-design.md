# 桌宠窗口看房间

设计基线为 origin/main 的 9194f8d。建议先交付 B 的生活状态和插画小窗，再以 C 为目标增加按需 3D。只有用户看向房间时才值得付出 3D 成本。两阶段共用同一份生活记录，可独立验收。

## 用户看见什么

馨语留在房间时，桌面入口显示一扇小窗。点开先看到当前活动，例如“窗边看书”，以及与地点配套的插画。若已安装房间且启用动态预览，首帧就绪后原位换成同一地点和动作的 3D 画面。未安装、加载失败或省电模式继续显示插画。旁边的“叫她出来”和桌宠入口的直接呼叫都可唤回她，回来后小窗显示房间空置。进入完整房间仍走原有入口。

生活状态由主进程单独持有，包含所在端、地点、活动、开始与预计结束时间、随机种子和版本号。用本地规则安排行走、看书、休息，在活动到期或读取快照时推进；系统休眠后按当前时间定位到一段合理活动，跳过中间表演与通知。插画、3D 和对话只消费这份快照。切换场景时先定位再播放动作，不把推演出来的活动写成用户亲历的共同记忆。

## 三条路径的增量成本

比较基线为同机已开启桌宠，CPU 为整机百分比，内存为新增工作集。下表为原型预算假设，非整机验收值。CPU 给宽区间以涵盖物理、贴图回读、进程间传输与呈现。功率为敏感性分析用的假设区间，尤其受独显能否休眠影响。

|路径|运行方式和体验|CPU|GPU|内存|增量功率及 8 小时耗电|
|---|---|---|---|---|---|
|A 常驻 3D|隐藏主窗，离屏相机 320×180、5 fps 持续绘制，压缩后由现有桥转给桌宠，开窗可立即出画|0.1–3%|估算绘制时间占比约 0.6–2.2%，另计回读与显示|400–750 MiB|2–15 W，16–120 Wh|
|B 状态和插画|在现有进程按活动边界更新，桌宠加载一张预制插画，关闭后停止绘制|空闲 <0.1%，切图短峰另测|关闭时新增 3D 工作为零，开窗仅切图合成，预计平均 <1%|1–20 MiB|0–0.5 W，0–4 Wh|
|C 按需 3D|关闭同 B，打开先看插画，启动一个只读渲染子进程，关窗释放|关闭同 B，打开按 A，启动峰值另测|关闭同 B，打开按 A|关闭同 B，打开约 401–770 MiB|假设观察占 10%，约 0.2–1.95 W，1.6–15.6 Wh，另计冷启动|

A 能呈现连续姿态，但代价是无人观看时仍占着显卡。B 对设备最友好，插画只表达活动类别。C 能看见真实场景，但不能还原用户关窗前每一根骨骼的位置；需要活动阶段、相机位置与动画进度来掩盖切换。

### 数字从哪里来

- 本机 Windows，Ryzen 9 8940HX、32 逻辑线程、16 GiB 内存、RTX 5060 Laptop。仓库已有全房间录制期间的 284 次采样，Godot 均值为整机 CPU 2.89%、595.2 MiB，峰值 705.5 MiB。降帧能省绘制工作，角色和场景资源仍须驻留。[完整房间记录](../godot_room/PHASE4-REPORT.md)
- 独立场景实测每帧 GPU 中位数为 RTX balanced 1.24 ms、610M low 4.40 ms；乘以 5 帧/秒得到约 0.62% 和 2.2% 的绘制时间占比。分辨率和场景不同，不能当任务管理器占用率。离屏预览应显式调度 SubViewport 更新，隐藏原生窗口本身不能保证纹理刷新。[场景测量条件](../godot_room/art/docs/PERFORMANCE.md) · [Godot SubViewport](https://docs.godotengine.org/en/stable/classes/class_subviewport.html)
- 本次离线微测用 Python Pillow 创建一张 320×180 灰度噪声图（标准差 64）转 RGB，循环向内存编码 JPEG quality 70，立即解码。三轮各 500 次，每帧编解码合计进程 CPU 时间 1.594、1.156、1.125 ms；单帧 29,486 字节，5 fps 约 144 KiB/s。噪声样本用于估算传输量；未覆盖 Godot GPU 回读、Electron 绘制或桥接。不采集桌面图像。
- 三种路径使用相同思考策略。生活推进、开窗、唤回默认各增加 **0 次模型请求，费用为 0**。用户随后发起对话才按既有路径计费。若把每分钟一次“想法”替换成本地规则，每在线 8 小时可少发 480 次请求。举例假设每次输入 500、输出 80 token，输入/输出单价分别为每百万 token 1/4 元（仅算例），每天 0.3936 元、30 天约 11.81 元。若未来允许每小时一次则每天 8 次、约 0.00656 元。实际按供应商单价及含重试的真实用量代入；后台默认关闭模型思考，启用需有每日硬上限，开关和计数独立于渲染帧率。

## 同一会话内传帧

现有 electron/roomSession.js 只监听随机 127.0.0.1 端口，检查 POST、Origin、Host、Bearer；一次性票据 30 秒内兑换会话 token。沿用该桥，预览和完整房间互斥，不另开监听。复用已验证的房间制品，安装下载不能由后台生活触发。未来在同一白名单增加预览专用二进制帧路由，在现有 JSON 解析前分流。预览会话仅授权引导、保活及上传帧，引导不发聊天历史，不开放 turn、intent、receipt 或 TTS。后端 API token 仅留主进程侧，渲染页只通过验证发送方的 IPC 订阅内存中的最新帧。

固定 JPEG 格式、320×180、每帧最多 128 KiB、每秒至多 5 帧；先限流、限实际读取字节和图片声明尺寸，再解码。只留最新帧，至多一个在途，慢消费者丢帧。只截房间相机，不读桌面、不落盘。关闭小窗撤销会话，取消请求、断连接、杀子进程树并释放图像；退出走现有 before-quit 清理，并覆盖启动中的异步回调。主进程异常退出时不能依赖 before-quit，子进程需保活超时自退或绑定 Windows kill-on-close Job。重开用新票据，旧 token 永不复用。

## 叫她出来时谁能说话

主进程按单调递增的世代号分配唯一说话权。逻辑上的居住地与是否存在预览进程分开记录；现有 main.js 以 roomSession/roomStarting 表示房间占用，实施时须区别只读预览与完整房间。预览永不持有说话权。

1. 点击或语音命中呼叫后，主进程原子进入“返回中”，递增世代号，禁止旧端继续开口；重复呼叫共用本次交接。把这次用户输入缓存一次，不同时交给两个回复入口。
2. 撤销旧端的主动对话、模型流、TTS 和音频播放，保存最后已确认的位置、活动和已送达对话游标。两端在播放、显示回复及写记忆之前都核对世代号；旧流即使晚到也丢弃。
3. 收到停止播放确认，或超时后确认旧房间进程树已结束，才将说话权授予桌宠。无法确认则保持静音、允许重试。桌宠出现并消费一次缓存输入，可基于“刚才在窗边看书”自然回应。预览启动晚到时按旧世代直接关闭。进入完整房间执行相反方向的同一交接。

## 实施顺序和验收

1. **状态与插画**。先实现 B，旧配置缺字段保持现有体验，显式开启后生效。用固定时钟验证跨活动、休眠恢复、用户在桌面时房间无人；断网运行 8 小时，新增模型请求为零。
2. **交接与退出**。用假模型延迟回包、慢 TTS、双击、启动中退出及强杀父进程覆盖竞争条件。连续切换 100 次，同一时刻最多一端可播放，每个输入至多交付一次，无遗留进程或监听。旧票据重放、跨会话 token、越权发言和超大帧均须拒绝。
3. **动态小窗试验**。先验隐藏时是否真出新帧，检查其序号、时间戳、姿态及切回插画。比较桌宠基线、B 关/开窗、A 常驻、C 开关循环，固定亮度、电源模式、模型与相机，每组预热 2 分钟、采样 10 分钟、重复三次。记录进程树 CPU/工作集、GPU 引擎及专用显存、有效帧率、回读延时、首帧 P95；用墙插功率计或同电池电量区间的放电率扣除基线，分开报告插电和电池结果。优先验证独显是否在关窗后重新休眠。以关窗后 10 秒释放渲染进程、首帧 P95 ≤3 秒为初始验收目标；不达标保留插画，动态预览继续实验。真实低帧整链路与瓦数均待本阶段验证。

## 按需 3D 原型实测 · 2026-11-02

**决策：保留 C，但打开小窗时必须先显示 B。** 三次重新启动 Godot 均超过 3 秒首帧目标。隐藏窗口稳定出帧和正常关闭通过了短测，可以进入桌宠显示链路试验。三次不足以给出可靠的 P95。

**测量边界。** 使用前述本机、RTX 5060 Laptop、Godot 4.6.3 Forward+、低档卧室和仓库自带的公开 Shino 角色及待机动作。首次资源导入在计时前完成；每轮新建进程，未清系统缓存。通过原生窗口句柄异步隐藏主窗，320×180 SubViewport 以 5 fps 显式绘制、读回、编码 JPEG。经匿名管道传 Base64 到 Python/Pillow，解码后逐帧检查主窗不可见、图像尺寸和色差。三轮分别收到 55/55 张哈希不同的有效帧。前 5 帧用于预热，余下 50 帧约 10 秒用于计算稳态指标。GPU 数值仅为视口绘制耗时，不含整条链路；CPU 和工作集仅统计 Godot 引擎。没有调用模型、打开监听端口或启动 Electron。

**释放与限制。** 父进程发出关闭信号后等待控制台启动器退出，并检查实际 Godot 进程已消失。三轮均在 1 秒内完成正常退出。仅验证了进程级释放；显卡重新休眠、驱动显存回落、整机功耗、异常杀父和用户看到首帧的实际延迟仍待联调。隐藏主窗时直接设置 Godot 主窗口 visible 会被引擎拒绝；仅等待绘制回调也未得到可用的隐藏窗口基线。正式样本使用异步 Windows 隐藏和显式绘制的组合。

**复现。** 从本分支复制已跟踪的 godot_room 到临时目录，用 Godot 4.6.3 控制台程序执行 `--headless --path <临时工程> --import`。在仓库根目录使用安装了 psutil 和 Pillow 的 Python 执行以下命令。测量脚本会启动三轮，每轮有 45 秒超时保护，只需保留下表所列类型的汇总指标。

```powershell
python scripts/room_preview_probe/measure.py "<Godot 控制台 exe>" "<已导入的临时 godot_room 目录>"
```
