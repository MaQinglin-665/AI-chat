## 已复现并修复

| 问题 | 用户影响 | 修复 |
| --- | --- | --- |
| 已输出文字后的异常被吞掉，并启动下一条回退路径 | 两份生成结果可能拼成一句话 | Chat、Responses、Ollama 已输出文字后向上传递错误；首字前保留兼容回退 |
| `[DONE]` 被忽略，或 Ollama 同时带正文和 done 的包跳过结束检查 | 回复结束仍等连接关闭 | 终止标记立即结束迭代，关闭响应上下文；保留末包正文 |
| 前端每收到一个数据块就重置首字计时 | 持续心跳可让界面一直等待 | 从开始读取响应体计算固定首字期限；首字后恢复既有读取逻辑 |
| 前端结束及部分错误路径未释放 reader，取消操作可能卡住 | 连接占用、错误或完成通知延后 | finally 统一取消未结束流并释放锁，取消不阻塞返回 |

部分回复失败现在会明确报错，用户需要重新发起请求；这是避免混合回复的有意行为。首字期限不覆盖请求头等待，也不限制首字后的总生成时长。
