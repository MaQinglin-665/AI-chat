## 视觉方向与范围

采用 design-taste-frontend 的 app-screen 流程，先核对项目实际DOM/CSS/字体/数据，再用浏览器看图、修正与检查。

- 浅色方向：`framed-sheet`，seed **1147155304**；深色方向：`true-black-flat`，seed **1257220883**，均使用 `keep palette,type`。
- 取其信息分层、实色表面、克制边界与状态着色，保留已有 `tokens.css` / `chatPolish.css` 的樱花色和系统字体。
- **有理由的偏离**：自动建议的侧栏/L形或T形应用壳不适用于现有桌宠聊天，本任务不重建导航/舞台，故保留聊天区域布局。夜色背景保留现有品牌紫色温度而非改成纯黑；浅色为同一聊天组件层级的提案，不是新增全局主题功能。没有反复随机抽样来追求另一套外观。
- 产品的识别来自“馨语桌宠”、自己的“馨”字标、樱花色、普通聊天与任务相邻的阅读顺序；没有引入第三方插画、贴图、头像、图标或新字体文件。
- 三方案回答同一问题：**“这个任务目前怎样，我接下来需要做什么？”** 待审批时主操作是查看/批准完整计划，运行时看真实可用进度，结束时看核对与异常。

## 示例数据

同一个虚构任务“整理课程资料”，目录是演示路径，未进行真实文件操作。两次移动：课程提纲.pdf→资料/课程提纲.pdf；示意图.png→图片/示意图.png。新建两个分类目录，修改0、删除0。三个计划步骤只是计划，不代表progress_count=3时完成三步。

运行图的“已收到3条进度更新”只演示接口的事件计数；不画百分比、虚构完成步骤或剩余时间。故意保留0项，未把零值替换成成功徽标。各状态只是同一任务的不同时间切片，不能把状态参考图理解为十个真实任务。

所有示例姓名/文案/路径、时间、计划、进度、结果与错误都要在阶段2接入公开任务数据后替换；标题只作确定性短摘要，不调用新的大模型标题接口。

## 截图检查

- 3方案×深浅两主题×1440px/390px，共12张聊天区域稿；另有2张窄屏审批详情与2张完整状态参考，共16张PNG。
- 另以320/360/760px与长目录路径压力检查：没有页面横向溢出；数据换行，主操作在卡片/详情内，未借隐藏重要审批信息解决溢出。
- 窄屏采用16px外边距、可读正文/说明层级、至少44px的主要按钮；详情滚动区与固定操作区分别留位。
- 视觉复核修正了：小字比例过高、窄屏12px边缘过近、浅色面板边界过重、C方案摘要与详情双主按钮、B方案摘要过高等问题。
- 设计技能源码lint无FAIL/WARN；真实浏览器在1440/768/390px对三方案深浅色分别检查。最终结果和PNG维度/摘要见截图目录说明；检查报告与可运行原型源只保留在本地输出，不进入产品。
- 原型渲染检查无pageerror、无外网或任务请求；未调用authFetch/任务接口、没有读取真实token/配置、没有音频播放。

直接看图后的结论：A阅读顺序最接近当前任务计划界面，审批信息集中；B明显降低占高但需要二次展开；C能读长计划，但在既有窄消息栏中优势消失。推荐A，并统一窄区域详情模式。
